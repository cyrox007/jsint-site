# SEO JSInteractive

Документ фиксирует поисковую архитектуру публичной части. Цель — не
«набить ключевые слова», а дать поисковым системам понятные отдельные
страницы под реальные пользовательские задачи и поддерживать техническую
индексацию без дублей.

## Карта поисковых интентов

| Страница | Основной интент |
| --- | --- |
| `/` | full-stack разработчик, backend-разработка, self-hosted проекты, портфолио разработчика |
| `/workspace-organizer` | self-hosted рабочее пространство, заметки, задачи, файлы, командная работа |
| `/projects/vanga` | ML-модель, прогноз рейтинга фильма, CatBoost / IMDb experiment |
| `/projects/the-game` | JavaScript Canvas игра, браузерная игра |
| `/projects/churchcms` | self-hosted CMS для приходов, епархий и церковных организаций |
| публикации | узкие информационные запросы по теме конкретной статьи |

Демонстрационная форма `/demo/vanga` не является отдельной поисковой
посадочной страницей: она имеет `noindex` и canonical на
`/projects/vanga`.

## Реализовано в коде

- уникальные title и description для главной и продуктовых страниц;
- canonical URL;
- robots meta и HTTP `X-Robots-Tag` для служебных/дублирующих страниц;
- OpenGraph и Twitter Card с крупным изображением;
- sitemap с `lastmod`;
- robots.txt с sitemap и очисткой tracking query-параметров;
- ProfilePage + Person для автора;
- ItemList для портфолио проектов;
- BlogPosting + BreadcrumbList для публикаций;
- SoftwareApplication + BreadcrumbList для проектов;
- дата публикации/изменения и wordCount для статей;
- использование первого изображения статьи в social/structured metadata;
- внутренняя перелинковка с главной на отдельные страницы проектов.

## Контентная стратегия

Для роста органического трафика новые публикации должны отвечать на один
конкретный поисковый вопрос и ссылаться на релевантный проект или другую
статью только там, где это действительно помогает читателю.

При подготовке статьи:

1. один понятный H1;
2. содержательный title, не копирующий механически H1;
3. description, который кратко объясняет пользу страницы;
4. логичная структура H2/H3;
5. собственные примеры, схемы, скриншоты и выводы;
6. ссылки на связанные внутренние материалы;
7. заполненные категория и технологии;
8. обновление материала при заметных изменениях проекта или технологии.

Не создавать несколько страниц с почти одинаковым текстом под варианты
одного поискового запроса.

## После выкладки

1. Проверить `/robots.txt` и `/sitemap.xml` с публичного домена.
2. Отправить sitemap в Google Search Console и Яндекс Вебмастер.
3. Запросить переобход главной и ключевых проектных страниц.
4. Проверить structured data валидатором Google Rich Results / Schema.org.
5. Проверить canonical и статус индексации для `/demo/vanga`.
6. Следить за запросами, показами, CTR и страницами входа, а не только за
   средней позицией.
7. Улучшать страницы с показами и низким CTR через title/description и
   более точное соответствие интенту.
8. Регулярно обновлять публикации и связывать их с релевантными проектами.

## Ограничение

Техническая SEO-подготовка делает сайт доступным и понятным поисковым
системам, но конкретная позиция зависит также от качества и полноты
контента, конкуренции по запросу, внешних упоминаний, истории домена и
поведенческих/поисковых сигналов. Позиция №1 не может быть гарантирована
изменениями шаблонов или мета-тегов.
