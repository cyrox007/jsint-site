# Нативные push-уведомления панели управления

Панель JSInteractive использует стандарт Web Push и установленную PWA. Для администратора не требуется отдельное приложение, topic URL, аккаунт ntfy или Bearer token.

Важно: стандарт Web Push использует push-инфраструктуру самого браузера/ОС для доставки системного уведомления. Это не отдельный интегрируемый сервис JSInteractive: администратор ничего не регистрирует и не настраивает у стороннего провайдера.

## Что происходит при первом включении

1. Администратор открывает `Уведомления → Настройки` по HTTPS.
2. По нажатию «Включить уведомления» браузер запрашивает системное разрешение.
3. Service Worker создаёт `PushSubscription` с публичным VAPID-ключом JSInteractive.
4. Подписка сохраняется в `admin_web_push_subscriptions` и привязывается к текущему администратору.
5. Новые события центра уведомлений доставляются на все активные устройства администратора.

Приватный VAPID-ключ создаётся локально при первом обращении к Web Push. В production по умолчанию он хранится в `/var/lib/jsint-site/webpush-vapid.pem` с правами `0600`. Путь можно переопределить переменной `WEB_PUSH_VAPID_PRIVATE_KEY_PATH`. Файл должен сохраняться между обновлениями: удаление ключа инвалидирует существующие браузерные подписки.

Опционально можно задать `WEB_PUSH_VAPID_SUBJECT` в формате `mailto:admin@example.com` или HTTPS URL. Если переменная не задана, адрес формируется из `SITE_BASE_URL`.

## Развёртывание

После обновления кода необходимо установить Python-зависимости, выполнить `alembic upgrade head` и перезапустить web/worker процессы. Каталог, в котором хранится VAPID-ключ, должен быть доступен на запись пользователю приложения при первом запуске.

Service Worker не кэширует административные HTML/API-ответы. Push содержит только заголовок, краткое описание, приоритет и ссылку на защищённую карточку события; диагностические архивы, ключи и вложения не передаются.

## Диагностика

Экран настроек показывает состояние текущего браузера: отсутствие HTTPS, неподдерживаемый Web Push, запрет системных уведомлений или активную подписку. Кнопка «Отправить тест» выполняет доставку сразу и возвращает количество успешных и ошибочных подписок.

Ответы `404` и `410` от push endpoint означают устаревшую подписку; сервер удаляет её автоматически. Для временных ошибок подписка сохраняется, а текст последней ошибки записывается в БД.
