# Эксплуатация CMS и публичных витрин

## Назначение

`jsint-site` используется как единый центр управления публикациями, рубриками, страницами, медиа, пользователями, лицензиями и релизами.

Встроенная публичная часть JSInt и внешние витрины, например Logos, имеют собственный дизайн и собственное SEO. Общими остаются база контента, административная часть и публичный API.

## Рабочие сайты

Каждая витрина представлена сущностью `Site`.

Для встроенного JSInt:

- сайт должен быть активным;
- сайт отмечается как основной для встроенной витрины;
- дизайн и SEO формируются шаблонами `jsint-site`;
- настройки главной редактируются в разделе сайта.

Для Logos:

- создаётся отдельный активный сайт с ключом `logos`;
- указывается публичный адрес Logos;
- origin Logos добавляется в список разрешённых origin публичного API;
- SEO и внешний вид формируются в `logos-frontend`.

## Ведение публикаций

Рабочий сайт выбирается в административной части. Рубрики и публикации всегда фильтруются по выбранному сайту.

Редактор публикации содержит:

- название и основной текст;
- рубрику и тип материала;
- публичный URL;
- статус публикации;
- SEO встроенного сайта;
- структурные поля выбранной витрины;
- размещение материала на дополнительных сайтах;
- вставку изображений из медиатеки;
- предпросмотр черновика;
- предупреждение о несохранённых изменениях.

Для встроенного JSInt предпросмотр использует реальный публичный шаблон. Для внешней витрины используется нейтральный предпросмотр данных, потому что окончательный дизайн принадлежит внешнему frontend.

## Структурные профили

Общие поля не зависят от витрины. Специальные поля хранятся в версионированном профиле конкретного сайта.

Сейчас предусмотрены `logos.article@1` и `logos.lecture@1`.

Профили хранятся раздельно по ключу сайта. Одна публикация может одновременно размещаться на JSInt и Logos, при этом данные Logos не становятся частью интерфейса JSInt.

При несовместимом изменении структуры существующего профиля создаётся новая версия схемы; смысл старых полей молча не меняется.

## Медиатека

Файлы принадлежат выбранному сайту. Изображение можно выбрать непосредственно из редактора публикации. В публичный HTML попадают только безопасные изображения с допустимым `src`; опасные URI отбрасываются очисткой HTML.

Для содержательных изображений следует заполнять alt-текст в медиатеке до вставки в публикацию.

## Настройки главной JSInt

Из кода в настройки вынесены содержательные элементы главной: первый экран и подписи кнопок, текстовые секции, навигация, метрики, карточки «О проекте», опыт работы, порядок и видимость блоков, подвал и SEO.

Навигация, метрики, карточки и позиции опыта редактируются как динамические списки: их можно добавлять и удалять без изменения шаблонов.

Сетка, CSS-классы, визуальные компоненты и поведение остаются в коде.

## Пользователи

Раздел «Пользователи» позволяет создавать учётные записи, менять имя и фамилию, менять пароль и удалять пользователя.

Пароль хранится только в виде bcrypt-хеша. Нельзя удалить собственную активную учётную запись или последнего администратора.

Доступ к административной части дополнительно ограничивается `ADMIN_EMAILS`. Создание записи пользователя само по себе не добавляет email в конфигурацию разрешённых администраторов.

## Проверка JSInt → Logos

Перед выкладкой пройти сценарий:

1. Убедиться, что сайты JSInt и Logos активны.
2. Для Logos проверить публичный URL и разрешённый origin.
3. Создать рубрику Logos.
4. Создать публикацию Logos или включить размещение существующей публикации на Logos.
5. Заполнить профиль `logos.article@1` или `logos.lecture@1`.
6. Открыть нейтральный предпросмотр и проверить текст, профиль и изображения.
7. Опубликовать размещение.
8. Проверить `/api/public/v1/sites/logos/bootstrap`.
9. Проверить список публикаций и отдельную публикацию по slug.
10. Убедиться, что ответ содержит `X-JSInt-Public-API: jsint-public-v1`.
11. Открыть материал в Logos и проверить собственные title, description, canonical, OpenGraph и JSON-LD.
12. Проверить мобильное отображение.

## Техническая проверка перед выкладкой

После восстановления GitHub Actions либо локально:

    python -m unittest discover -s tests
    alembic upgrade head

Проверить `/healthz`, главную, `/robots.txt`, `/sitemap.xml` и `/api/public/v1/sites/logos/bootstrap`.

Для Logos:

    npm ci
    npm run verify
    npm run build

## Граница с контуром релизов

Лицензии и релизы остаются самостоятельной частью `jsint-site`. Изменения CMS не должны менять формат лицензий, подпись релизов, локальный signer или update API.
